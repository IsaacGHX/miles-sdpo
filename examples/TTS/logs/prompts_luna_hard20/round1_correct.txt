You are given one or more worked solutions that were graded CORRECT. Distill only the valid, reusable reasoning principles that are genuinely supported by those solutions into 1–3 small, self-contained skill blocks.

Output EXACTLY this format and nothing else:

[Knowledge/Rule]
<A precise, transferable theorem, identity, method, invariant, interpretation rule, or verification procedure. State hypotheses and boundary conditions when they matter. Do not give a roadmap for this particular problem.>
[Details/Examples]
<A short, self-contained example using different symbols, values, and context from the given problem. Demonstrate how the rule is applied, including a key check or limitation when useful.>

Hard constraints:
- Use the literal headers [Knowledge/Rule] and [Details/Examples] for every block.
- Output only the blocks; no introduction, conclusion, commentary, solution, or answer.
- Extract only reasoning that is correct and reusable. Do not merely repeat a step from the supplied solution unless it expresses a general principle.
- Prefer actionable skills: state what to compute, compare, enumerate, test, or prove, and what condition validates the result.
- Preserve quantifiers and model assumptions. Distinguish “for one fixed object” from “for every object,” independent random choices from deterministic choices, and necessary conditions from sufficient conditions.
- Include endpoint, sign, parity, domain, integrality, and strict-versus-nonstrict inequality conditions whenever omitting them could change the conclusion.
- For optimization or extremal claims, require both directions when appropriate: a valid universal bound and a construction or argument showing sharpness. Do not present an unproved bound as a theorem.
- For counting or probability, specify the sample space, whether order matters, whether choices repeat, and how fixed initial conditions affect the count.
- For algebraic or asymptotic coefficients, retain all terms that can contribute to the requested order and state why discarded terms cannot contribute.
- For geometry, state the configuration hypotheses and check that a claimed symmetry, tangency, perpendicularity, or area/volume argument actually applies.
- If the source problem is incomplete or ambiguous, do not infer an omitted target or invent an “intended” answer. Extract only general methods for handling explicitly stated information and, if relevant, a rule to identify insufficient data without resolving the instance.
- Do not copy distinctive numbers, names, expressions, answer formats, or conclusions from the given problem into the rule or example when doing so would reveal its answer.
- Never state the given problem’s final answer, answer choice, requested constant, count, or an equivalent encoded form. The example must not be a disguised computation of that answer.
- Avoid vague advice such as “be careful,” “use algebra,” or “apply symmetry” unless the block states exactly when and how.
